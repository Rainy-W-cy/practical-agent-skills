# 参考图与复杂图重画流程

当用户要求临摹、复刻、重画、仿照、参考图片制作 PPT 图，或要求根据文档内容生成类似参考图的 PPT 页面时，使用本流程。适用对象包括论文图、架构图、关系图、分类图、流程图、截图、草稿图、手绘图和视觉参考图。

## 强制顺序

```text
确认任务目标
-> 读取源材料和参考图
-> 分析文档内容
-> 分析参考图视觉结构
-> 输出解释计划或图形规格
-> 用户确认
-> 选择生成模式
-> 渲染图形并插入 PPT
-> 导出预览
-> QA 对比
-> 修复后再次 QA
```

不得在用户确认解释计划或图形规格前直接创建最终 PPT 图。

## 内容优先级

- 用户提供文档、PDF、报告或笔记时，这些材料是内容依据。
- 参考图默认只作为视觉结构、布局、配色和表达方式参考。
- 只有用户明确要求“照抄参考图内容”时，才把参考图中的文字和关系视为内容来源。
- 不得从模糊图片中编造不可读标签、数字、公式、箭头关系或分组名称。
- 图片中文字不清楚时，标记为“需确认”，并要求用户提供高清图、原文档或允许简化。

## 解释计划

普通参考图任务至少输出一份解释计划，包含：

- 参考图文件或截图来源。
- 目标页数和页面用途。
- 要复现或借鉴的视觉结构。
- 可读文字、不可读文字和需用户确认的内容。
- 主要形状、颜色、区域、箭头、连接关系和层级。
- 是否需要完全复刻、概念性重画，还是只借鉴风格。
- 预计使用的实现方式：PowerPoint 原生对象、SVG/draw.io、插入图片，或混合方式。

在完成上述分析前，不得直接进入坐标式绘制。仅凭肉眼估计坐标直接写 COM 形状和线条，容易导致箭头方向、残差回路、层级遮挡、标签遮挡和局部比例错误。

## 图形规格

复杂图必须先输出图形规格并获得确认。复杂图包括密集论文图、多分支分类图、架构关系图、多模块流程图、包含大量小标签或交叉连线的图。

图形规格至少包含：

- 节点清单：每个节点的文字、类别、层级和来源。
- 区域清单：中心区、分支区、模块区、图例区、讨论区等。
- 连接清单：每条线或箭头的起点、终点、方向、语义、是否需要折线/回路/跳线，以及是否应避开其他对象。
- 布局方案：大致方位、对齐方式、留白和视觉重心。
- 层级顺序：背景容器、模块框、连接线、标签、强调符号的绘制顺序和置顶/置底策略。
- 色彩方案：继承参考图、继承模板，或重新设计。
- 内容映射：文档中的哪些事实映射到图中哪些节点和区域。
- 不确定项：不可读文字、缺少依据的关系、可能需要简化的内容。

## COM 原生绘图前检查

当选择 PowerPoint COM 原生对象绘制时，先形成可执行的绘图规格，而不是直接写散乱坐标：

- 对象注册表：给每个模块、容器、标签、符号和连接线命名，后续连接和 QA 均引用名称。
- 锚点规则：为每个模块定义上、下、左、右、中点等连接锚点，箭头优先连接锚点，不随意连接到视觉中心。
- 路由规则：复杂回路、残差连接、跨模块连接先写出路径，如“从 A 右侧出发 -> 水平到 x -> 垂直到 B -> 指向 B 左侧”。
- 绘制顺序：先画背景容器和分区，再画内部模块，再画主干箭头和回路，最后画标签、加号、位置编码等前景符号。
- 遮挡检查：所有前景标签和底部输入输出模块必须最后置顶，避免被大容器或后续形状覆盖。
- 特殊符号检查：`×`、波形、加号、公式符号等若字体或形状不稳定，应先用简单替代表达或单独矢量小组件，并在 QA 中明确检查。
- 预演检查：对于箭头密集图，先用低成本草图或对象表检查连接关系，确认后再运行 COM 生成最终 PPT。

## 生成模式

复杂图生产前必须让用户确认一种模式：

| 模式 | 适用情况 | 代价 |
| --- | --- | --- |
| 高保真视觉复刻 | 用户更重视外观接近参考图 | SVG/vector 插入为主，PPT 内完全编辑性有限 |
| PPT 原生可编辑简化版 | 用户更重视后续在 PowerPoint 中编辑 | 外观和复杂度需要简化 |
| 混合版 | 用户同时需要较好外观和部分可编辑 | 使用 SVG/vector 作为基础，关键文字或标注尽量做成 PPT 原生对象 |

不要默认承诺复杂图既高保真又完全原生可编辑。两者冲突时必须说明取舍。

默认优先保证 PowerPoint 后续可编辑性，但只在很简单的图和普通流程图中直接使用 PowerPoint COM 原生绘制。稍微复杂的模块图、关系图、架构草图、分组箭头图，优先使用已安装的 draw.io skill/capability 生成源图，再使用本机 draw.io 软件导出 SVG 和 PNG。不要修改 draw.io skill 或工具本身的规则，只把 draw.io 作为图形制作后端。切换前必须说明：哪些内容会变成整体 SVG/矢量资产或 PNG 图片，哪些内容仍保留为 PowerPoint 原生可编辑对象。

依赖要求：本流程需要 draw.io skill/capability 负责生成或维护 `.drawio` 源图，并需要本机 draw.io 软件负责导出 SVG 和 PNG。如果本地没有安装 draw.io 软件，或当前会话无法调用 draw.io skill/capability，应先告知用户，并询问是否需要安装或启用；未经确认不要临时改用其他外部绘图方案。

## 复杂度分级与路线确认

在绘制前必须先判断参考图复杂度，并向用户确认路线：

| 复杂度 | 判定 | 默认路线 |
| --- | --- | --- |
| 很简单 | 少量节点、少量直线箭头、无嵌套容器、无密集标签 | 可直接使用 PowerPoint 原生对象 |
| 稍复杂 | 模块图、架构图、关系图、分组箭头图、encoder/decoder block、多个容器或多层连接 | 先询问并推荐 draw.io 源图 + SVG/PNG 导出 |
| 复杂 | 密集论文图、多分支 taxonomy、复杂网络、很多小标签/跨层连接 | 必须 diagram-first；优先 draw.io/SVG，必要时 PNG fallback |

若参考图不是“很简单”，不得默认直接用 PowerPoint COM 原生绘制。必须先让用户在以下路线中确认一种：

1. draw.io 路线：生成 `.drawio` 源图，由 draw.io 软件导出 SVG 和 PNG，检查后插入 PPT。
2. PPT 原生可编辑简化版：可编辑性优先，但外观和结构会简化。
3. 混合版：SVG/PNG 作为主体，关键标题、注释或可改文字尽量使用 PPT 原生对象。

用户未确认路线前，不得开始最终绘制。

## 实现规则

- 很简单的图和普通流程图，优先使用 PowerPoint 原生形状、连接线和文本框，保证后续可编辑。
- 稍微复杂的图，例如模块图、关系图、架构图、分组箭头图，优先用 draw.io skill/capability 制作或维护 `.drawio` 源文件，再用本机 draw.io 软件导出 SVG 和 PNG。
- 使用 draw.io 时，先用 PNG 预览检查布局、箭头、层级和视觉效果；再检查 SVG 中的文字是否乱码、缺字、丢失标签，以及是否满足 PowerPoint 兼容性。只有 SVG 检查通过后，才通过 COM 导入 PPT。
- PPT 兼容 SVG 不应包含 `foreignObject`、嵌入式 `data:image` 文本 fallback，或 draw.io 的 `Text is not SVG - cannot display` 提示。出现这些内容通常说明 draw.io 使用了 HTML 标签/富文本 fallback，浏览器可能能显示，但 PowerPoint 可能显示警告、丢字或渲染异常。
- 为提高 SVG 可导入性，draw.io 源图应尽量使用普通文本和独立文本框，少用 HTML 富文本、`<font>`、复杂下标、混合颜色、内嵌图片式文字。需要红色/下标/分行时，优先拆成多个普通文本对象，而不是在一个 HTML 标签里混排。
- 如果 SVG 不合规、导入 PowerPoint 后视觉损坏、文字乱码、标签丢失或渲染不稳定，可以改用 draw.io 导出的 PNG 直接插入 PPT。使用 PNG fallback 前必须说明：该图在 PPT 内主要作为图片存在，后续不方便逐个编辑图形元素；`.drawio` 源文件仍应作为可编辑源保留。
- 密集论文图、复杂架构图和多分支关系图，继续使用 diagram-first 工作流；优先 draw.io/SVG，必要时再考虑其他可控矢量方案。
- PowerPoint COM 主要负责装配到模板、插入图形、放置标题、说明、页脚和可编辑补充标注。
- 不把大量小字烘焙进 AI 生成图片，除非用户明确接受不可编辑且需人工复核的风险。
- 生成式图片只能用于封面、背景、概念性装饰或非事实插图，不能替代论文证据图、实验结果、数据图、产品截图或文本密集型事实图。
- PPT 页面中的正文、标题、公式和关键标注应尽量保持为 PowerPoint 原生可编辑内容。

## QA 规则

正式输出必须导出预览并检查：

- 文字是否可读，是否有乱码、缺字、错字或文字溢出。
- 节点数量、区域层级和连接方向是否符合已确认规格。
- 每条箭头、折线和回路是否连接到正确对象，是否出现穿越模块、方向相反、过度倾斜或遮挡文字。
- 颜色、布局、视觉重心和相对位置是否接近确认目标。
- 文档内容和图形节点是否一一对应，是否出现无来源信息。
- 插入的 SVG、图片或矢量图是否清晰，比例是否变形。
- draw.io 路线必须同时检查 PNG 预览、SVG 文本和 SVG 的 PowerPoint 兼容性；SVG 乱码、标签缺失、包含 `foreignObject`、包含嵌入式文本图片 fallback，或包含 `Text is not SVG - cannot display` 时，不得导入 PPT 作为正式 SVG 图。若改用 PNG fallback，必须重新检查插入 PNG 后的 PPT 预览。
- 模板继承是否被破坏，页边距和标题区是否冲突。

修复后必须重新导出受影响页面的预览，或进行等效视觉检查。不能只说“已修复”而不复查。

正式图形最多执行两次预览/QA 检查，除非用户明确要求继续。第二次 QA 后如果图形仍未达到确认规格，必须中断继续修补，向用户说明剩余差距，并建议切换生成模式、提供高清参考图、降低可编辑性要求，或改用其他外部矢量/diagram-first 方案。
