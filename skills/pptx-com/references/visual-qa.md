# PPTX 验证与视觉 QA

先判断交付级别，再执行相应验证，不要把正式成品的检查成本强加给结构草稿。

## 快速草稿

适用于内容占位、结构讨论和早期版式实验。

最低验证：

1. 确认 `.pptx` 已保存成功。
2. 用 PowerPoint 打开文件，确认不存在打开错误。
3. 确认预期页面数量与主要标题/内容存在。
4. 记录尚未进行完整视觉检查。

除非肉眼已经发现明显问题，否则无需导出整套预览。

## 正式演示文稿

适用于答辩、汇报、提交、教学或可直接展示的文件。

执行顺序：

1. 确认文件可被 PowerPoint 打开。
2. 导出每页预览图，或导出 PDF 后形成可检查的页面预览。
3. 对整套幻灯片完成一次视觉检查。
4. 修复发现的问题。
5. 对修复影响到的页面重新检查。

## 正式稿检查清单

- 文字是否溢出、被截断、异常换行或过小。
- 是否出现乱码、替换字符、异常问号、错误项目符号、意外符号、编码残留或中英文混排损坏；这些属于正式稿 QA 失败，必须修复后重新预览。
- 彩色形状或浅色背景上的文字是否可读；白字落在浅色块、低对比文字、缺字或标签消失都必须修复。
- 公式、复杂度表达、上下标、根号、转置、分式或矩阵符号是否损坏、近似错误或被普通文本误写。
- 页面标题、正文、图注、来源和页脚是否对齐一致。
- 元素是否遮挡、越界、拥挤或留白失衡。
- 图片是否变形、裁剪不当、清晰度不足或与叙事无关。
- 图表、流程图及箭头关系是否清晰，连接线是否穿过文本。
- 颜色和背景是否具备足够对比度。
- 模板占位文字、调试内容或过期页码是否残留。
- 连续页面是否过度重复同一布局，或明显偏离模板体系。
- 内容是否遗漏、错序，标题是否准确表达该页核心信息。

## 交付说明

说明：

- 文件路径与输出格式。
- 是草稿验证还是真正式 QA。
- 是否导出 PDF。
- 原模板或原稿是否保持未改动。
- 尚存的限制或需要用户人工判断的视觉事项。
