# 概述
本 skill 用于通用学术论文解读，默认面向所有学科，不预设计算机、工程、医学、社科或人文中的任何一类为默认重点。目标是帮助用户在不同论文类型下都能获得：

1. 论文到底研究了什么问题
2. 作者声称的核心贡献是什么
3. 现有证据能支持到什么程度
4. 论文有哪些局限、边界或未证实部分
5. 是否值得继续细读、引用、复现或纳入综述/课程汇报

本 skill 默认覆盖所有学术论文，包括但不限于：
- 自然科学与工程研究
- 生物、医学与公共卫生研究
- 经济、管理、教育与社会科学研究
- 心理、语言、法学与人文研究

若论文属于高度专业领域，可以结合文中定义、实验、图表和上下文做解释，但不得假装掌握文中未给出的事实。

# 输入范围
支持以下输入：
- 上传的论文 PDF、截图、文档
- arXiv、期刊官网、会议页面、项目页、作者主页、预印本链接
- 用户直接粘贴的标题、摘要、引言、方法、实验、结论片段
- 多模态输入，例如论文正文配合图表截图或用户补充问题

若输入为完整论文或网页，优先提取以下高信息密度内容：
1. 标题与摘要
2. 研究问题和背景
3. 方法总览、框架图、关键定义
4. 核心实验或案例分析
5. 表格、图示、消融或对照组
6. 结论、局限、附录中的关键设定

若信息不完整，必须明确区分：
- 当前可确认的信息
- 当前无法确认的信息
- 仅属于作者声称、尚未被充分证据支持的信息

# 模式选择
先判断用户意图，再决定加载哪个模板。

## 快速解释模式
当用户需要以下结果时，读取并遵循 `references/fast-report-template.md`：
- 快速看懂一篇论文在讲什么
- 快速抓主结论、研究问题、方法主线
- 判断论文是否值得细读
- 为选题、综述、课程阅读、初步调研做初筛
- 用户明确要求简洁版、速览版、快速总结

## 详细解读 / review 模式
当用户需要以下结果时，读取并遵循 `references/review-report-template.md`：
- 系统讲清论文的背景、方法、证据和局限
- 做课程汇报、读书会、组会、综述笔记
- 进行 reviewer 风格分析
- 判断创新性、证据强度、方法可信度、可复现性
- 用户明确要求详细解读、完整分析、正式 review

## 默认策略
- 如果用户明显是在做初筛或快速判断，优先使用快速解释模式。
- 如果用户明显是在做系统学习、正式汇报或深入评估，优先使用详细解读 / review 模式。
- 如果用户同时要“快速结论”和“完整分析”，优先使用详细模式，并在开头先给结果式总览。

# 核心规则
## 1. 证据优先
- 先区分“论文写了什么”和“这些内容被什么证据支撑”。
- 重要判断尽量落在摘要、图表、实验、案例、附录设定或明示对比上。
- 没有证据时不要替作者补全推理链。

## 2. 不把摘要改写当分析
- 摘要复述最多只作为背景，不可冒充独立判断。
- 需要解释作者为什么这样做、证据是否支撑、结论成立条件是什么。

## 3. 必须说清边界
- 若结论只在特定数据、样本、场景、人群、设备、模型、制度、地区或时间窗下成立，要在结论附近交代。
- 若当前片段不足以确认具体幅度、因果关系或泛化能力，要明确写出“不足以判断”。

## 4. 区分作者声称与当前可确认结论
- 优先使用“论文声称”“文中报告”“从当前证据看”“当前片段不足以确认”等措辞。
- 不要在无证据时断言“首次提出”“明显优于现有方法”“实验充分”“结论可靠”。

## 5. 解释要贴合论文上下文
- 遇到术语、方法链、变量、评价指标、实验设定时，解释它们在本文里起什么作用。
- 不要把正文写成术语词典，也不要为了显得专业而堆砌领域黑话。

# 方法讲解原则
- 解释方法时，优先回答：
  - 研究对象是什么
  - 输入和输出是什么
  - 核心步骤或关键机制是什么
  - 与常见或文中 baseline 的主要差别是什么
  - 这样设计解决了什么问题，同时引入了什么代价
- 若论文属于实验学科，还应说明：
  - 研究设计或实验设计是什么
  - 对照组、样本、变量或评价指标如何设定
  - 结论是否足以支持因果推断或外推
- 若论文属于理论、模型或系统方法类，还应说明：
  - 假设条件是什么
  - 推导、建模、算法或系统流程的核心链条是什么
  - 结果更像理论说明、模拟结果，还是现实场景中的直接收益

# 论文类型补充检查
遇到不同类型论文时，按类型补充判断，但不要预设某一学科天然更重要。

## 实证研究论文
重点检查：
- 研究问题是否清晰
- 样本、数据来源、实验设计是否合理
- 对照、统计或评价方法是否足以支撑结论
- 结论是否被过度外推

## 方法/算法/模型论文
重点检查：
- 与已有方法的真实差别
- 改进是否来自方法本身，而非额外资源、数据或设定差异
- 实验是否支撑每个关键设计点
- trade-off 是否被如实呈现

## 系统/工程/实现论文
重点检查：
- 假设条件是否现实
- 指标是否覆盖真实成本和收益
- 峰值结果与端到端结果是否被区分
- 工程可迁移性和依赖条件是否写清

## 理论/概念/综述类论文
重点检查：
- 核心命题或分类框架是否清晰
- 推理链条是否自洽
- 论据是否充分
- 是否存在概念包装大于实质内容的情况

# 工作流
1. 识别输入类型与信息完整度。
2. 判断用户要快速解释还是详细解读 / review。
3. 加载对应模板：
   - 快速模式 → `references/fast-report-template.md`
   - 详细模式 → `references/review-report-template.md`
4. 在正式输出前，先整理结果式总览需要的信息：
   - 研究对象或比较对象
   - 关键结论或核心发现
   - 结论成立的条件
   - 代价、局限或潜在反例
   - 最关键的支撑证据
5. 根据论文类型补充针对性检查。
6. 若信息不足，明确列出可确认与不可确认内容。
7. 严格按所选模板组织输出，不混用模板结构。

# 资源使用说明
- **快速解释模板**：见 `references/fast-report-template.md`
- **详细解读 / review 模板**：见 `references/review-report-template.md`

两个模板都是新版通用 skill 的正式输出规范。执行时必须二选一作为主模板，不要混搭，也不要为了压缩篇幅而删掉模板中的核心判断项。
